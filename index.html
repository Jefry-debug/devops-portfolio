PROJECT 3

Mindtrack – Production Application Deployment using DevOps

A production-oriented DevOps deployment workflow covering GitHub, Docker, Docker Hub, Jenkins CI/CD, Kubernetes, AWS EKS and CloudWatch monitoring.

CompletedGitHub Repository ↗

Technologies Used

AWS EC2GitHubDockerDocker HubJenkinsKubernetesAWS EKSCloudWatchNginxLinux

What I Implemented

  • Created and maintained the Mindtrack GitHub repository containing Docker and Kubernetes configuration files.
  • Containerized the production-ready dist/ files using Nginx and built the Docker image with docker build -t brain-app ..
  • Tagged and pushed jefryjo/mindtrack:latest to Docker Hub.
  • Configured Jenkins on AWS EC2 to clone the repository, build the Docker image, authenticate to Docker Hub, push the image and deploy to Kubernetes.
  • Created Kubernetes Deployment and LoadBalancer Service configuration and prepared the application for AWS EKS using eksctl and kubectl.
  • Used Amazon CloudWatch for monitoring AWS resources and EC2 metrics.

DevOps Workflow

GitHub→Jenkins→Docker→Docker Hub→Kubernetes / EKS→CloudWatch

Challenges Solved

  • Resolved Jenkins Docker daemon permission errors by adding Jenkins to the Docker group.
  • Corrected the Jenkins Git configuration to use the main branch.
  • Configured AWS credentials for Jenkins and verified access with aws sts get-caller-identity.
  • Corrected Docker Hub authentication using --password-stdin and Jenkins credentials.
  • Changed the Docker repository from uppercase jefryjo/Mindtrack to lowercase jefryjo/mindtrack.
  • Reviewed and configured required EKS IAM permissions after EKS API permission errors.
